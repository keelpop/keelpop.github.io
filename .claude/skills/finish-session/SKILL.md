# セッションの締め方

コンテナは回収される。**push していないものは存在しないのと同じ。**
過去に2回、成果ブランチごと作業が消えた。1回はこの仕組みを作っている最中に起きた。

上から順に実行する。飛ばさない。

## 1. 変更を全部コミットする

```bash
git status --short
```

未追跡ファイルを見落とさない。`git add -A` の前に必ず一覧を見る。
新規ファイルを作りっぱなしでブランチを移動すると、そのまま消える（INC-0010）。

コミットメッセージは、変更したファイル名と、何をなぜ変えたかを書く。
`Update file` のような、内容を述べていないメッセージは残さない（INC-0007）。

## 2. push する

```bash
git push -u origin "$(git rev-parse --abbrev-ref HEAD)"
```

失敗したら4回まで、2秒・4秒・8秒・16秒あけて再試行する。
**push が通らないままセッションを終えない。**

push すると `autoflow` が動き、安全条件を満たすものは main へ直接マージされる（PR は作らない）。
条件を満たさない場合は「手動で確認してほしい: <ブランチ名>」という Issue が立ち、
理由がそこに書かれる。保留は失敗ではない。設定や保護機構に触れる変更は、
必ず人が一度見る設計になっている。

自動マージを止めたいときは、リポジトリ直下に `.no-automerge` という空ファイルを置く。

## 3. 検査を通す

```bash
python3 tools/check_site.py
```

ERROR が残っていたら直す。CLAUDE.md の §4 に直し方の対応表がある。
WARN は残してよい。

## 4. NOW.md を書き換える

`.claude/state/NOW.md` を開き、**追記ではなく置き換える。**

- `次の一手` は、次のセッションがそれだけ読めば再開できる粒度で1行。
- 終わった `待ち` の行は消す。残す価値のある判断だけ「直近の決定」に1行移す。
- 「直近の決定」が5件を超えたら、古いものを `.claude/state/DECISIONS.md` に押し出す。
- **新しい `待ち` を書くなら、`due:` と `default:` を必ず添える。**
  期限が来たら無人セッションが `default:` を実行する。
  この2つが無い待ちは放置される。実際に2件、14日止まった（INC-0004, INC-0005）。

40行・2KB を超えると検査が落ちる。溢れたら押し出す。

## 5. 失敗があれば記録する

手戻り・やり直し・想定外の詰まり・ユーザーからの訂正があったなら、
`.claude/state/INCIDENTS.jsonl` に1行足す。**原因の分析はしない。事実だけ書く。**

```json
{"id":"INC-00NN","ts":"YYYY-MM-DD","src":"self","sig":"既存のsigから選ぶ","sev":1,"session":"","detail":"何が起きたか","auto":false}
```

`sig` は既存の行から選ぶ。当てはまるものが無ければ `"other"` にして `detail` に書く。
**新しい `sig` を作ってよいのは `/rule-gardener` だけ。** 種類が無限に増えると集計できなくなる。

`sev` は 1=手戻り / 2=作業消失・公開の失敗 / 3=データ損失。

ここに書いた記録が、週次の棚卸しでルールの材料になる。
書かなければ同じ失敗が繰り返される。それが41セッション分の実測だった。
