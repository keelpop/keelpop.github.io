# __PROJECT__

## §0 憲法（自動更新禁止。ここを変更する変更は自動マージされない）

1. **1セッション = 1成果物 = 1ブランチ。** 変更が5ファイルまたは300行を超えたら、
   そこで一度コミットして push する。残りは NOW.md の「次の一手」に書いて終える。
2. **無人セッション（Routine が起動したもの）はユーザーに質問してはならない。**
   判断できないときは、その手順に書かれた `default:` を実行する。
   `default:` が無い事態なら、何もせず INCIDENTS.jsonl に記録して終える。
3. **作業したら必ず push してから終わる。** 未 push で終わらない。
4. **NOW.md を更新せずにセッションを終えない。**
5. 「待ち」を作るときは、必ず `due:`（期限）と `default:`（期限が来たら何をするか）を書く。
   これが無い待ちは放置される。
6. ルールを1件足すなら、必ず1件退役させる。active は20件・この CLAUDE.md は120行が上限。
7. 秘密情報・個人情報・APIキーをリポジトリに書かない。

## §1 地図（毎回ここから読む）

| 知りたいこと | 見る場所 |
|---|---|

| セッションの締め方 | `/finish-session` |

- `tools/` は仕組み専用。サイト用の生成スクリプトは `scripts/` に置く。

## §3 機械が勝手にやること（あなたが気にする必要はない）

- `tools/check_site.py` が品質とルール系の健全性を検査する。
- GitHub Actions を入れた場合は、push のたびに検査し、
  安全条件を満たす `claude/*` ブランチを main へ自動マージする。保留は Issue で知らせる。

## §4 やってはいけないこと

- `main` に直接コミット・push しない。`claude/*` ブランチを使う。
- `git push --force`（`--force-with-lease` は可）。
- `.github/` `.claude/` `tools/` を「ついでに」変更しない。
  ここを変える変更は自動マージされず、必ず人間の目に触れる。これは意図的な設計。
